{{#finding}}

Full-size photos on the practice-area pages Fail

SpeedLCPEffort S
Found
Two photos were uploaded as JPEGs {{metric audit.facts.photo_upload_px}} and served at full size: pines.jpg at {{metric audit.facts.pines_kb}}, plus ridge.jpg on the Personal injury page. No responsive sizes, no modern format, no lazy loading.
Why it matters
These are the Family law and Personal injury pages, the ones a search ad or a referral link lands on. On a phone their main image arrives late ({{metric now.family-law.lcp_s}}, {{metric now.personal-injury.lcp_s}}) against Google's {{metric audit.facts.lcp_good_s}}, and visitors on mobile data start leaving well before that.
Evidence
{{page family-law lcp_s,weight_kb,savings_kb.uses-responsive-images,savings_kb.modern-image-formats}} {{page personal-injury lcp_s,weight_kb,savings_kb.uses-responsive-images,savings_kb.modern-image-formats}}
Fix
Re-encode as WebP, {{metric audit.facts.webp_px}} at {{metric audit.facts.webp_quality}}, with generated sizes (srcset); set width and height, lazy-load below the fold. The pines photo goes from {{metric audit.facts.pines_kb}} to about {{metric audit.facts.pines_webp_kb}} with no visible loss.
{{#finding}}

Eighteen font weights from Google, plus three icon-font stylesheets Fail

SpeedFCPEffort S
Found
The page builder requests the Newsreader family in every weight and italic ({{metric audit.facts.google_font_weights|range}}) from fonts.googleapis.com, and loads Font Awesome's {{metric audit.facts.icon_stylesheets|word}} for the handful of icons in the trust strip.
Why it matters
Every visitor's browser connects to a third-party server and waits for its stylesheet before drawing any text. First text appears late ({{metric now.*.fcp_s|range}}). The firm's headline and phone number should be visible in under a second.
Evidence
fonts.googleapis.com/css?{{metric audit.facts.google_font_query}} ({{metric audit.facts.google_css_requests}} + font files) {{metric now.*.render_blocking|range}} (Lighthouse "render-blocking-resources")
Fix
Turn off the builder's Google Fonts option, self-host Newsreader as one variable web font ({{metric audit.facts.self_host_axis|range}}) plus one italic file with font-display: swap and a preload. Switch the builder to inline SVG icons so the icon-font CSS never loads.

{{#finding}}

Scripts and stylesheets loading on pages that do not use them Needs work

SpeedRequestsEffort M
Found
jQuery, jQuery Migrate, the builder's frontend runtime and widget chunks, the form plugin's submission script, the emoji script and the block-library stylesheet load on all seven pages. None of the pages use sliders, tabs or popups, so most of it does nothing.
Why it matters
The site makes {{pair *.requests}}. Each one is a round trip on a phone connection, and the home page shifts while late stylesheets arrive ({{metric now.home.cls}}). It also means every plugin update is a chance for something unneeded to break the page.
Evidence
{{page home requests,weight_kb,render_blocking,cls}} {{page contact requests,weight_kb,cls}} Scripts on every page: jquery.min.js, jquery-migrate.min.js, webpack.runtime.min.js, frontend-modules.min.js, frontend.min.js, form-submission.js, wp-emoji-release.min.js
Fix
Remove the parent theme CSS, block-library CSS, icon font, default form styles, jQuery, builder frontend JS and the emoji script on pages that do not need them; set the builder's CSS print method to internal and inline the remaining small stylesheets; add page caching with long cache headers on uploads. Scoped so that adding an interactive widget later re-enables the builder script on that page only.
