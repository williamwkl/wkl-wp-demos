01

Full-size photos on the practice-area pages Fail

SpeedLCPEffort S
Found
Two photos were uploaded as {{audit.facts.photo_upload_px}} px JPEGs and served at full size: pines.jpg at {{audit.facts.pines_kb}} KB, plus ridge.jpg on the Personal injury page. No responsive sizes, no modern format, no lazy loading.
Why it matters
These are the Family law and Personal injury pages, the ones a search ad or a referral link lands on. On a phone the page's main image appears at {{now.family-law.lcp_s|s1}} s and {{now.personal-injury.lcp_s|s1}} s. Google's "good" line is {{audit.facts.lcp_good_s}} s, and visitors on mobile data start leaving well before that.
Evidence
Family law LCP {{now.family-law.lcp_s|s1}} s page weight {{now.family-law.weight_kb}} KB Lighthouse: responsive-images savings {{now.family-law.savings_kb.uses-responsive-images}} KB, modern-formats savings {{now.family-law.savings_kb.modern-image-formats}} KB Personal injury LCP {{now.personal-injury.lcp_s|s1}} s page weight {{now.personal-injury.weight_kb}} KB Lighthouse: responsive-images savings {{now.personal-injury.savings_kb.uses-responsive-images}} KB, modern-formats savings {{now.personal-injury.savings_kb.modern-image-formats}} KB
Fix
Re-encode as WebP at {{audit.facts.webp_px}} px with generated sizes (srcset) and quality {{audit.facts.webp_quality}}, set width and height, lazy-load below the fold. The {{audit.facts.pines_kb}} KB photo becomes about {{audit.facts.pines_webp_kb}} KB with no visible loss.
02

Eighteen font weights from Google, plus three icon-font stylesheets Fail

SpeedFCPEffort S
Found
The page builder requests the Newsreader family in every weight and italic ({{audit.facts.google_font_weights|range}}) from fonts.googleapis.com, and loads Font Awesome's {{audit.facts.icon_stylesheets|word}} stylesheets for the handful of icons in the trust strip.
Why it matters
Every visitor's browser connects to a third-party server and waits for its stylesheet before drawing any text. First text appears at {{now.*.fcp_s|s1|range}} s on every page. The firm's headline and phone number should be visible in under a second.
Evidence
fonts.googleapis.com/css?family={{audit.facts.google_font_query}} ({{audit.facts.google_css_requests}} external CSS request + font files) Render-blocking resources per page: {{now.*.render_blocking|range}} (Lighthouse "render-blocking-resources")
Fix
Turn off the builder's Google Fonts option, self-host Newsreader as one variable woff2 ({{audit.facts.self_host_axis|range}}) plus one italic file with font-display: swap and a preload. Switch the builder to inline SVG icons so the icon-font CSS never loads.

03

Scripts and stylesheets loading on pages that do not use them Needs work

SpeedRequestsEffort M
Found
jQuery, jQuery Migrate, the builder's frontend runtime and widget chunks, the form plugin's submission script, the emoji script and the block-library stylesheet load on all seven pages. None of the pages use sliders, tabs or popups, so most of it does nothing.
Why it matters
{{now.*.requests|range}} requests per page on a site that needs {{after.*.requests|range}}. Each one is a round trip on a phone connection, and the home page shifts layout (CLS {{now.home.cls}}) while late stylesheets arrive. It also means every plugin update is a chance for something unneeded to break the page.
Evidence
Home: requests {{now.home.requests}}, weight {{now.home.weight_kb}} KB, render-blocking {{now.home.render_blocking}}, CLS {{now.home.cls}} Contact: requests {{now.contact.requests}}, weight {{now.contact.weight_kb}} KB, CLS {{now.contact.cls}} Scripts on every page: jquery.min.js, jquery-migrate.min.js, webpack.runtime.min.js, frontend-modules.min.js, frontend.min.js, form-submission.js, wp-emoji-release.min.js
Fix
Remove the parent theme CSS, block-library CSS, icon font, default form styles, jQuery, builder frontend JS and the emoji script on pages that do not need them; set the builder's CSS print method to internal and inline the remaining small stylesheets; add page caching with long cache headers on uploads. Scoped so that adding an interactive widget later re-enables the builder script on that page only.

FindingsSEO, accessibility, maintenance

SEO

  • Every page has a unique title and meta description, one H1, a canonical URL and Open Graph tags (Yoast SEO).
